# Campaign release v0

`campaign-release/v0` is the provisional archival boundary for Portage
Command. It compiles one named dossier closeout profile into:

- its transitive canonical-source and evidence coverage;
- a public inventory with payload class, provenance, and license status;
- explicit replay lanes and replay debt;
- a projected profile verdict for publication artifacts generated by the
  release itself;
- a content-addressed archive plan that is writable only when every gate
  passes.

It remains a derived read model:

```text
authority: DERIVED_READ_MODEL_ONLY
graph_effect: NONE
```

A materialized release records what was packaged and how it can be checked. It
does not prove a portrait claim, discharge a leaf, or write a graph event.

## Compile a plan

The synthetic fixture is complete except for a live clean-source audit:

```text
gp campaign-release fixtures/release/synthetic/release.json --format human
```

The JC draft consumes the publication profile and provides the portrait-audit
and release-manifest placeholders through declared generators:

```text
gp campaign-release fixtures/release/jc_publication/release.json \
  --source-root ../math-stuff --format human --require-ready
```

`--require-ready` exits 1 after printing a valid blocked plan and exits 0 for a
materializable plan. Invalid schemas, stale dossier bindings, unsafe paths, and
attempted materialization of a blocked plan exit 2.

## Coverage

Coverage is computed from exact evaluated criterion references, not from
descriptions:

| profile criterion | required release records |
|---|---|
| every profile | all canonical dossier sources |
| `CLAIMS_PRESENT` | every named claim's evidence |
| `LEAVES_PRICED`, `LEAVES_CLOSED` | leaf evidence and evidence for every retired representation |
| `ARTIFACTS_PRESENT`, `ARTIFACT_REPLAY_PASS` | the named artifacts |
| `SOURCE_FRESH` | canonical dossier sources (already unconditional) |

An omitted required record becomes `COVERAGE_MISSING`. A missing dossier
artifact remains missing unless the dossier declares an exact `generated_by`
contract and the release binds that same generator to a safe path, provenance,
and license status. This is how a generated release manifest or portrait audit
can satisfy its own presence criterion without pretending to create a
manuscript, formal interface, or proof receipt.

## Inventory policy

Each selected source or artifact has one safe, portably unique release path and
declares:

- payload class: `SOURCE`, `COMPACT_RECEIPT`, `REGENERABLE`,
  `HEAVY_DISCOVERY`, or `EXTERNAL`;
- license status: `CLEAR`, `REVIEW`, or `EXCLUDE`;
- a provenance note.

Only `CLEAR` items whose dossier disposition is `INCLUDE` may be materialized.
Paths cannot be absolute, escape the archive, include `.git`, collide by case,
or occupy generated `manifest.json`, `REPLAY.md`, or `SHA256SUMS` paths.

## Replay debt

Selected `PROVED`, `CHECKED`, or `CONDITIONAL` claim-support, formal-interface,
and mechanism-ceiling artifacts are load-bearing. Unless replay is explicitly
`NOT_APPLICABLE`, each must have a passing dossier replay and a release lane
that contains the exact replay command. The current lane classes are `FAST`,
`FORMAL`, `REPLAY`, `EXHAUSTIVE`, and `EXTERNAL`; the names expose expected
operational cost but grant no authority.

## Materialization gate

Materialization requires all of the following at one observation:

1. the bound dossier digest matches;
2. the projected closeout profile is `READY`;
3. the source commit and every selected payload digest match in a clean tree;
4. transitive coverage is complete;
5. replay, licensing, and public-disposition debt are empty;
6. every archive path is safe and unique.

Run:

```text
gp campaign-release RELEASE.json --source-root CHECKOUT \
  --output-dir NEW_DIRECTORY --require-ready
```

The output directory must not already exist. Files are copied into a sibling
staging directory, their normalized digests are rechecked after planning, and
the staging directory is atomically renamed only after success. A finished
archive contains the selected payloads plus:

- `manifest.json` — the complete derived release observation;
- `SHA256SUMS` — normalized digests for every payload and `REPLAY.md`;
- `REPLAY.md` — the exact commands grouped into declared lanes.

`manifest.json` cannot contain its own digest. Its identity is instead the
deterministic `plan_fingerprint`; `SHA256SUMS` deliberately covers the copied
payload and replay document rather than claiming a circular self-hash.

## Current JC result

The draft release now retires two former publication blockers: it generates the
content-addressed release manifest and exact portrait dependency audit. It
still refuses materialization for real remaining work, including the
manuscript, incomplete non-S2 price cards, unreplayed load-bearing exact notes,
and a clean current-source observation. Exact S2 closure remains a separate
gold-profile concern.

## Deferred until another campaign uses it

- RO-Crate export;
- environment lockfiles and clean-clone runner automation;
- archive signing, remote upload, DOI minting, or publication APIs;
- incremental/prior-release lineage;
- schema freeze as v1.

The native manifest should stabilize through a non-JC release before any
interchange wrapper becomes authoritative infrastructure.
